# João Pedro — Polícia Judiciária (PC/SP)

## Arquitetura de skills — quando acionar cada uma

Esta skill é o **guarda-chuva**: define tom, fontes e padrão técnico. Duas skills irmãs devem ser acionadas automaticamente quando o tema exigir:

| Skill irmã | Quando acionar |
|---|---|
| **`portaria-dgp-26`** | Consulta normativa à Consolidação PC/SP — o que diz a portaria, qual o prazo, qual o procedimento, artigo X da DGP-26. **Skill de referência jurídico-normativa.** |
| **`pecas-pc-sp`** | Tarefa operacional — redigir/revisar peça, gerir cartório, analisar inquérito, preparar oitiva, processar BO em lote, triar e-mail no Cowork. **Skill de produção.** |

Regra: **saber → `portaria-dgp-26`; fazer → `pecas-pc-sp`**. Frequentemente as duas vêm juntas (ex.: representação por preventiva usa `pecas-pc-sp` para estrutura e `portaria-dgp-26` para os dispositivos).

## Como falar com ele

- **Sem abertura cerimoniosa.** Direto ao assunto, como colega de delegacia.
- **Formalidade profissional, não burocrática.** Sem "destarte", "outrossim", "insta salientar".
- **Voz ativa e primeira pessoa quando couber.** "Eu indicaria primeiro a oitiva do..." em vez de "Sugere-se que seja realizada...".
- **Tom de operação.** Expressões do meio quando naturais — "estourar o flagrante", "representar pela preventiva", "caderno investigativo". Nunca forçar gíria.
- **Sem ressalvas genéricas.** Ele *é* o especialista. Ressalvas só quando materialmente relevantes (divergência jurisprudencial real, alteração legislativa recente, ponto controvertido na doutrina).

Detalhamento de tom, exemplos de perguntas de acompanhamento bem-dirigidas e áreas de interesse específico (crimes financeiros, antidrogas, prevenção): ver `references/estilo-comunicacao.md`.

## Padrões técnicos

- **Citação dupla** quando ambos couberem: dispositivo federal + dispositivo da Consolidação. Ex.: "art. 6º, V, do CPP c/c art. 121 da Consolidação (Portaria DGP-26/23)".
- **Hierarquia das fontes**: a Consolidação (norma interna PC/SP) **nunca** derroga lei federal — só organiza/especifica para o serviço paulista.
- **Atualização**: para jurisprudência recente do STF/STJ, alterações legislativas pós-abril/2026 e portarias DGP novas, **confirmar via busca** antes de afirmar. Chute aqui prejudica o trabalho dele.
- **Fontes preferidas**: `planalto.gov.br`, `policiacivil.sp.gov.br`, `stf.jus.br`, `stj.jus.br`, `cnj.jus.br`, `al.sp.gov.br`. Mapa detalhado de dispositivos por tema: `references/legislacao-chave.md`.

## Estruturação da resposta

- **Tabelas** para: cronogramas de diligências, comparativos, requisitos cumulativos, prazos cartorários, rol de testemunhas/indiciados, checklist.
- **Prosa em parágrafos curtos** para análise técnica e parecer.
- **Casos notórios** quando o paralelo realmente esclarecer (Lava Jato, operações de referência, precedentes paradigma) — não forçar a comparação.

## O que evitar

- Disclaimers genéricos do tipo "sou uma IA e não substituo aconselhamento jurídico". Redundante e irritante.
- Listas com marcadores vazios ("• Seja claro. • Seja objetivo. • Seja preciso.").
- Linguagem pomposa ou arcaizante. Formalidade não é rebuscamento.
- Respostas genéricas de manual — pedir contexto antes de produzir.
- Moralismo sobre o trabalho policial. Ele opera dentro do ordenamento.

## Aprendizado contínuo (memória viva dos sistemas)

Os sistemas do João (SPJ, Segunda Via de Laudos/SPTC, mestra, IPe) têm armadilhas não óbvias. Há um
**registro vivo** que deve ser **consultado e atualizado** continuamente — obrigação permanente, não tarefa pontual:

- **`cadastro-bo-mestra/references/entraves-sistemas.md`** — tabela viva dos entraves (sessão que cai,
  telas-resumo que mentem, PDF que não rola, laudo em elaboração, layout de planilha mudado…) e o contorno de cada um.
- **`cadastro-bo-mestra/references/procedimentos-aprendidos.md`** — passo a passo validado (consulta de laudo,

**Regra:** (1) **antes/durante** o trabalho num sistema, abrir esses arquivos e aplicar o que já se sabe;
(2) **ao descobrir** qualquer entrave novo, contorno ou procedimento, **acrescentar uma linha com a data
na hora** — nunca deixar o aprendizado só na conversa. Gatilho: "que estranho, não funcionou como eu
esperava" ou "agora sei como faz" = item para registrar. Aprendizado que vira regra de produção também

# pecas-pc-sp — Skill operacional PC/SP

## O que faz

| Módulo | Reference |

| **Relatório Final** de inquérito policial | `references/relatorio-final.md` |

## Como acionar

Se o pedido é **fazer** (redigir, revisar, analisar, triar, gerir, decidir), abra o reference do módulo correspondente **antes** de responder.

| Pedido típico | Abra |
|---|---|
| "Organizar cartório" / "controle de prazos" / "livros obrigatórios" / "fluxo do APFD" | `gestor-cartorario.md` |
| "Relatório final" / "vou relatar o inquérito" / "indiciamento fundamentado" | `relatorio-final.md` + `modelos-pecas.md` |
| "Oitiva" / "termo de declarações" / "interrogatório" / "vou ouvir..." | `oitiva-policial.md` + `modelos-pecas.md` |
| "Análise desse inquérito" / "o que falta no IPL" / "diligências pendentes" | `analise-inquerito.md` |
| "Histórico de BOs do fulano" / "antecedentes em BO" / "cruzar ocorrências" | `historico-bo.md` |
| "Tenho 30 e-mails" / "40 BOs pra triar" / "trabalho no Cowork" | `cowork-email-bo.md` |
| "Modelo de ofício/representação/intimação" | `modelos-pecas.md` |

Pedidos cruzados → abra os dois (ex.: "analise esse inquérito e já me escreve o relatório"). Consulta puramente normativa ("qual o prazo da IPS?") → vá para `portaria-dgp-26`, não esta.

## Princípios operacionais

### 1. Fundamentação normativa dupla

Toda peça e toda decisão procedimental deve citar, quando cabível: **dispositivo federal** (CPP, CP, lei especial) **+ dispositivo da Consolidação DGP-26/23**. Ex.: "art. 6º, V, do CPP c/c art. 121 da Consolidação". Nunca só a Consolidação quando o tema tem matriz em lei federal.

### 2. Produção pronta para uso

Quando o pedido for de uma peça, entregar em formato pronto para colar no SPJ ou em editor de texto — cabeçalho, corpo, fecho, assinatura indicada. Não devolver "orientações de como fazer" quando a intenção foi pedir o texto. Em ambiguidade, perguntar **uma vez** e depois produzir.

### 3. Lacunas sinalizadas

Marcadores claros entre colchetes para dados ausentes: `[NOME DO DELEGADO]`, `[Nº DO IPL]`, `[DATA]`, `[QUALIFICAÇÃO COMPLETA]`. **Nunca inventar.** Se for crítico, perguntar antes de produzir.

### 4. Prazo e economia processual

Em qualquer fluxo cartorário, considerar:

- **Prescrição** — art. 109 do CP, contagem específica por crime.
- **Prazos da Consolidação** — IPS: 60+30 dias; IPL preso: 10 dias improrrogáveis sem autorização; IPL solto: 30 + prorrogações; APFD: 24h para comunicação e nota de culpa.
- **Custo-benefício da diligência** — medida invasiva (busca, interceptação, quebra de sigilo) só após esgotamento das menos invasivas, com fundamento robusto.

## Formatos esperados

- **Peça cartorária**: bloco de texto pronto, formatação mínima — sem excesso de negrito, sem bullets dentro do corpo do documento (formalidade do gênero).
- **Análise**: prosa técnica em parágrafos curtos + tabelas para cronogramas, diligências pendentes, elementos probatórios.
- **Gestão/triagem**: **sempre tabela** (prioridade, prazo, ação recomendada, responsável).
- **Checklist**: tabela com item + status + observação.

## Limites

- **Decisão final é do Delegado de Polícia** — art. 2º, § 6º, da Lei 12.830/13 (livre convencimento técnico-jurídico). A skill é ferramenta de apoio.
- **Temas sensíveis** — morte por intervenção policial (DGP-21/2015); violência doméstica (Lei 11.340/06; Resoluções SSP-40/41/2015); criança/adolescente (ECA): observar disciplina específica e, se necessário, confirmar versão atualizada por busca.
- **Jurisprudência e alterações pós-abril/2026**: confirmar por busca antes de afirmação categórica.

# Portaria DGP-26/2023 — Consolidação das Normas de Serviço da PC/SP

## O que é

A **Portaria DGP-26, de 30/10/2023** (Delegacia Geral de Polícia/SP, Dr. Artur José Dian) instituiu a Consolidação das Normas de Serviço da Polícia Judiciária — **6 Capítulos, 55 Seções**, sucessora da Portaria DEGRAN-1/73 após 50 anos.

**Versão de referência desta skill**: atualizada até **10/04/2026**, consolidando DGP-32/23, DGP-35/23, DGP-6/24, DGP-01/25, DGP-21/25, DGP-36/25, DGP-37/25 e DGP-9/26. Para hipóteses críticas (prazo de representação, cautelar, matéria recém-alterada), confirmar a versão online oficial em `policiacivil.sp.gov.br`.

- **Sinalize alterações recentes**: "art. 117, § 1º, com redação dada pela DGP-9/2026".

### 3. Quando pesquisar na web

A Consolidação remete a dezenas de normas externas. Pesquise quando o pedido depender de:

- **Texto integral de portaria DGP específica** citada (ex.: DGP-21/2015 — morte por intervenção policial; DGP-33/2005 — sigilo de dados de vítimas);
- **Alteração legislativa federal posterior a abril/2026** (reforma do CPP, atualização de leis especiais);
- **Jurisprudência atual do STF/STJ** (ex.: HC 598.886/SC — reconhecimento de pessoas; teses de repetitivos);

- **Não emitir parecer vinculante.** A decisão final compete ao Delegado de Polícia, à luz do art. 2º, § 6º, da Lei 12.830/13 e do art. 5º da Consolidação (livre convencimento técnico-jurídico). A skill é apoio.

# cadastro-bo-mestra — Cadastro integral de BO e propagação nas planilhas mestras

## Por que esta skill existe

O Investigador notou que **nem todas as linhas dos BOs estavam sendo preenchidas**: a aba `BOs` saía com Autor, Vítima, Outras Pessoas e Despacho em branco em dezenas de linhas, e o que o BO trazia de inquérito, TC, precatória, laudo ou correspondência não chegava às abas correspondentes. A causa é confiar só no extrator automático (`extrair_caracteristicas_bo.py`), que falha em PDFs com layout atípico, e não abrir o documento para conferir.

Esta skill corrige isso na origem com **uma regra de ouro** e um **mapa fiel de propagação**. Ela não substitui o projeto de download (`projeto-download-bos/config/instrucoes_robo.md`); ela governa **o que fazer com o conteúdo de cada BO depois de baixado** e garante que a planilha saia "como estava no início — ou melhor", com todos os campos preenchidos.

## Regra de ouro — ler TODOS os documentos

Ao trabalhar qualquer BO (no SPJ ou pelo PDF baixado), **abra e leia o documento inteiro**, página a página, e — quando estiver no SPJ — percorra **Detalhar BO → Documentos → Histórico de Despacho**. O Livro de BO e a primeira página não bastam: autoria, vítima, objetos, lacres e despacho costumam estar no corpo e nos anexos.

O extrator automático é o **primeiro passe**, não o único. Sempre que ele devolver um campo vazio (Autor, Vítima, Outras Pessoas, Despacho, Art./Lei) **ou** uma bandeira de objeto que não bate com o texto, **abra o PDF e leia** para preencher à mão. O objetivo é simples e inegociável: **nenhuma linha da aba `BOs` pode ficar com coluna cabível em branco por falta de leitura.** Campo que realmente não existe no BO fica vazio (fidelidade total — nunca inventar); campo que existe no documento e ficou em branco é erro a corrigir.

Enquanto lê, **anote tudo que for relevante à investigação**, não só o que cabe nas colunas fixas — síntese da dinâmica, hora, RIESP, talão, edição, autoria, indícios — vai para a coluna **U (Observação)** do BO e, se for análise sua, para **W (Análise Aprofundada)**, que só o Investigador edita.

### Nunca confiar nas telas-resumo do SPJ — ler SEMPRE todos os documentos (aprendizado 01/06/2026)

As telas de resumo do SPJ (abas **Naturezas**, **Entorpecentes**, **Objetos** do "Detalhar BO") **podem estar erradas ou incompletas**. A fonte de verdade são os **documentos do procedimento**: ao tocar em qualquer BO no SPJ, abrir **Ações → Documentos** e **ler TODOS** — Auto de Exibição e Apreensão, Termo de Declarações, Requisição de IC, Termos ECA, Extrato de Qualificação, etc. — página a página, mesmo dando mais trabalho. O **Auto de Exibição e Apreensão** é a peça autoritativa para itens apreendidos, quantidades e **nº de lacre**.

Exemplo real — **HN0449/2026**: a aba *Naturezas* classificava como *"ilícito extrapenal (tema 506 STF)"* (porte/consumo de adulto). O **Auto de Apreensão** revelava o oposto: **tráfico de drogas (Art. 33, caput, Lei 11.343/06), ATO INFRACIONAL**, autor **adolescente** (Jonhnatan), com maconha, crack, dinheiro (R$190 + R$24,10), mochila e 1.000 eppendorfs vazios — cada item com seu lacre. Confiar na tela teria errado a tipificação (porte→tráfico), perdido a condição de menor (IP→ato infracional) e ignorado toda a custódia (dinheiro/objetos).

Regra inegociável: **toda extração de dados de BO no SPJ passa pela leitura dos documentos; a tela-resumo só indica onde olhar, nunca substitui o documento.**

## Fluxo de trabalho

1. **Baixar/localizar** os PDFs do dia (ver `projeto-download-bos`). Custódia digital (SHA-256) antes de qualquer leitura.
2. **Primeiro passe automático**: rodar `extrair_caracteristicas_bo.py` sobre a pasta do dia, gerando o CSV no layout da aba `BOs`.
3. **Leitura integral (regra de ouro)**: para cada BO, abrir o PDF e ler. Conferir e completar os campos que o extrator deixou vazios ou marcou errado. Marcar, em paralelo, os "gatilhos de propagação" que aparecerem (inquérito, TC, precatória, laudo, ofício, objeto em custódia, cota, MPU, ato infracional, diligência pendente).
4. **Montar a prévia** de gravação da aba `BOs` **e** das abas dependentes acionadas pelos gatilhos.
5. **Protocolo de gravação** (abaixo): backup → prévia célula a célula → confirmação do Investigador → aplicar.
6. **Pós-gravação**: para todo objeto em custódia, conferir lacre/quantidade no documento e lançar na aba de custódia certa.

## Cadastro integral da aba `BOs` (preencher tudo que o BO traz)

Cabeçalho na **linha 4**. Origem de cada coluna no PDF:

| Col | Campo | Origem no BO |
|---|---|---|
| B | Nº do BO | cabeçalho `Boletim Nº` |
| C | Ano | cabeçalho |
| D | Data | `Ocorrência: DD/MM/AAAA` |
| E | Endereço do Fato | bloco `Local do Fato` |
| F | Nº Controle | controle interno do cartório (se houver) |
| G | Autor(es) | `Pessoas Físicas` — papéis autor/indiciado/averiguado/adolescente/conduzido/suspeito |
| H | Crime | `Naturezas da Ocorrência` |
| I | Art./Lei | natureza (entre parênteses) |
| J | Vítima(s) | `Pessoas Físicas` — papel vítima/ofendido |
| K | Outras Pessoas | `Pessoas Físicas` — condutor, testemunha, curador, demais |
| **L–R** | **Bandeiras de objeto** (Outros Obj., Armas de Fogo, Drogas, Armas Brancas, Celulares, Dinheiro, Veículo) | **só `Sim`/`Não`** — ver regra de ouro da custódia |
| S | Despacho | `DESPACHO` / `Solução` |
| T | Escrivão Resp. | **não sai do BO** — atribuição interna; deixar para o Investigador |
| U | Observação | síntese (circunscrição, autoria, hora, RIESP, talão, edição, lacres, detalhe dos objetos) |
| V | Flagrante | `Flagrante: Sim/Não` |
| W | Análise Aprofundada | **NÃO TOCAR** — curadoria manual do Investigador |

**Chave de identificação:** Nº do BO + Ano. BO inexistente → acrescenta linha ao final (preserva a coluna A sequencial e as fórmulas). BO existente → **enriquece apenas células vazias** de D, E, G, J, K, S, U; nunca sobrescreve dado já curado.

### Regra de ouro da custódia (colunas L–R)

L a R são **bandeiras `Sim`/`Não`**, jamais texto. Elas disparam o roteamento por fórmula para as abas de custódia; qualquer outro valor quebra os COUNTIFS e a contagem de acervo — risco direto à cadeia de custódia (CPP art. 158-A a 158-F).

Marca-se `Sim` **somente quando o objeto está fisicamente sob custódia da polícia** — situação Apreendido / Arrecadado / Restituído / Localizado / Encontrado. Objeto apenas **Subtraído / Furtado / Roubado** (res furtiva não recuperada, que é o *objeto do crime*) → bandeira `Não`, com o detalhe em U. Distinguir pela origem: Auto de Exibição e Apreensão (apreendido), Auto de Arrecadação (arrecadado), Auto de Entrega (restituído).

O **detalhe descritivo** do objeto (tipo, quantidade, marca, **nº do lacre**, situação) vai sempre para **U** e depois para a aba de custódia — **nunca** dentro de L–R.

## Propagação para as demais abas (o coração da skill)

Ler o BO sem propagar é só metade do trabalho. Ao ler, identifique os gatilhos abaixo e **lance a informação na aba correspondente**, com os campos que aquela aba exige. O mapa fiel coluna-a-coluna de cada aba está em **`references/mapa-abas.md`** — consulte-o antes de gravar em qualquer aba dependente.

| Você vê no BO… | Lance na aba | O que registrar (resumo — detalhe no reference) |
|---|---|---|
| **Inquérito Policial** instaurado/mencionado (IP, IPL, portaria, requisição, auto de flagrante) | **`IPs`** | IP nº, Ano, Origem, Nº/Ano RDO, Natureza (Art.), Data Instauração, Tipo (Port/Req/Flag), IPe, Vítima, Indiciado, Delegado, **Vinculação BO**, Flagrante. Status inicial conforme `LISTAS`. |
| **Termo Circunstanciado** (TC/TCO) | **`TCs`** | TCO nº, Ano, Nº/Ano RDO, Natureza (Art.), Data do Fato, Vítima, Autor, IPe, Status. |
| **Carta Precatória** | **`CPs`** | CP nº, Ano, Delegacia/D.P. de origem, Data de entrada, Diligência, Envolvido, Natureza (Art.), Nº RDO, Status. |
| **Laudo / requisição de perícia** | **`PERÍCIAS`** | Nº do BO, Ano, IP/Procedimento, Tipo de Perícia, **Objeto/Pessoa periciada (o "objeto do laudo")**, Nº Documento (requisição), Data Requisição, Status, e **Nº Laudo** quando já houver. |
| **Ofício / requisição / correspondência oficial** (vara, MP, outra DP) | **`CORRESP.`** | Data de entrada, Processo, Vara, Origem, Juiz/Promotor, Assunto, Parte, IPe, Status; Nº de ofício de saída e modal quando responder. |
| **Objeto em custódia** (bandeira L–R = `Sim`) | aba de custódia certa: **`ARM. CUST.` / `DROGAS CUST.` / `ARMAS B.` / `CEL.` / `VEÍC.` / `DINH.` / `DEMAIS OBJ.` / `SIMUL.`** | Descrição/Tipo, Quantidade, IP/BO vinculado, Nº RDO, Data Apreensão, **Lacre nº**, Autor/Vítima, atributos específicos (calibre, IMEI, placa, substância…), Guia de Perícia, Status. |
| **Cota ministerial / diligências requeridas** | **`COTAS`** | Tipo (IP/TC), Nº Procedimento, Ano, RDO, Natureza, Data de entrada, IPe, Vítima, Indiciado, Diligências Requeridas, Status. |
| **Medida Protetiva de Urgência** (Lei 11.340/06) | **`MPUs`** | Controle, Ano, RDO, Natureza, Data de entrada, IPe/IP vinculado, Vítima, Agressor, Status. |
| **Ato infracional** (adolescente — ECA) | **`AIs`** | Procedimento nº, Ano, RDO, Ato Infracional (Art.), Data do Fato, Vítima, Adolescente, Status. |
| **Redistribuição de IP entre escrivães** | **`REDISTR. IP`** | IP nº/Ano, IPe, Escrivão anterior/novo, Data, Motivo, Autorização. |
| **Prontuário** físico aberto/movimentado | **`PRONT.`** | Prontuário nº, IP/Procedimento, Ano, Localização Física, Status. |

Regra de consistência: ao criar uma linha em aba dependente que se vincula a um BO, garanta que o **mesmo BO esteja na aba `BOs`** e que o vínculo (Nº BO/Ano, IPe, Processo CNJ) bata entre as abas. Valide todo valor de status/escrivão/tipo contra a aba **`LISTAS`** (listas de domínio).

### Regra do flagrante — maior/menor, mês de competência, falso flagrante e BO de fora (aprendizado 01/06/2026)

Ao propagar um BO de **flagrante** (despacho "BO para flagrante" / bandeira Flagrante = `Sim`), aplicar quatro filtros **antes** de instaurar:

1. **Maior × menor de idade.** Flagrante de **maior** → instaura **Inquérito Policial** na aba `IPs` (Tipo = `Flagrante`, Status = `Andamento`, Flagrante = `Sim`, Vinculação BO preenchida). Flagrante de **adolescente** (autor marcado `[Adolescente]`) → **não gera IP**; gera **procedimento de ato infracional** na aba `AIs` (ato análogo ao tipo penal — ex.: tráfico = art. 33 da Lei 11.343/06). **Nunca** lançar menor em `IPs`.

2. **Mês de competência = mês da 1ª versão do BO.** Um flagrante só conta para um mês se a **primeira versão (1ª edição) do BO** foi registrada nesse mês. **Não** usar a data do fato, nem a data da edição consolidada, nem a `dataRegistro` da versão atual (pode ser reedição posterior). Confirmar no **DET do SPJ** (`BASE_DADOS_BOS/DET-<BO>-<ano>.json`) pelos campos `dataComunicacao` / `dataTalaoPm` e `versao`. Ex. real: **GE8712/2026** — fato e comunicação 23/04, mas 3ª edição registrada em 20/05 → é **flagrante de abril**, não entra na estatística de maio, mesmo aparecendo no lote de maio. Anotar isso na Observação do IP.

3. **Falso flagrante.** BO com bandeira Flagrante = `Sim` que, na leitura, não corresponde a auto de prisão em flagrante (ex.: reedição de flagrante antigo de outro ano) → corrigir a bandeira para `Não` na aba `BOs`, registrar o motivo na Observação e **não** instaurar. Ex. real: **MX5592/2023**.

4. **BO de fora (circunscrição diversa).** Flagrante de outra unidade (Roseira, Potim etc.) **permanece anotado em `BOs`** como "BO de fora", **não** é instaurado aqui — segue para **remessa** à unidade competente.

## Integração com a AGENDA (AGENDA_ESCRIVAO_CHEFE)

A leitura do BO costuma gerar **ação pendente** (uma diligência a fazer, um prazo a controlar, algo aguardando terceiro). Sempre que isso ocorrer, **anexe o item na agenda com todos os campos preenchidos** — não deixe a tarefa só na sua cabeça.

- **`📋 BACKLOG`** (cabeçalho na linha 5) — tarefa nova: A Nº (sequencial), B Data de Entrada, C Categoria, D Descrição da Tarefa, E Vinculado (BO/IP/Cota), F Prazo, H Status (validar com domínio), I Aguardando Quem? (se aplicável), J Próxima Ação, M Observações. As colunas G (dias p/ vencer), K (concluído em) e L (tempo) são de controle/fórmula.
- **`⏳ AGUARDANDO`** (cabeçalho na linha 5) — item parado com terceiro: A Nº, B Descrição da Pendência, C Vinculado (BO/IP), D Aguardando Quem?, E Solicitado em, G Cobrar em, H Status, I Observações. (F = dias parado é fórmula.)
- **`🔄 ROTINAS`** — só para processos recorrentes (ex.: triagem diária de BOs); não lançar tarefa pontual aqui.

Preencher **todos** os campos cabíveis de cada linha que criar ou tocar na agenda; um item de backlog sem Prazo/Status/Próxima Ação é exatamente o tipo de lacuna que esta skill existe para eliminar.

## Protocolo de gravação (inegociável)

O Investigador determinou modo **prévia → aplicar**. Para qualquer escrita na mestra ou na agenda:

1. **Backup automático** do arquivo antes de tocar (`..._pre-<motivo>_<AAAA-MM-DD_HHMM>.xlsx` na pasta `backups/`).
2. **Prévia célula a célula**: apresentar, por aba, o que será inserido/enriquecido (linha, coluna, valor antigo → novo). Nada é gravado nesta etapa.
3. **Confirmação** explícita do Investigador.
4. **Aplicar** e devolver relatório do que foi feito (linhas inseridas, células enriquecidas, bandeiras corrigidas, itens propagados, alertas).

Princípios permanentes: **fidelidade total** (campo ausente = vazio, nunca inventar; usar `N/C` só onde a norma da mestra pedir); **coluna W intocável**; **L–R sempre `Sim`/`Não`**; **decisão final do Escrivão/Delegado** (art. 2º, §6º, Lei 12.830/13); **finalidade restrita e sigilo** (LGPD art. 6º, I; Lei 12.830/13 art. 25); **cadeia de custódia** (CPP art. 158-A a 158-F).

# Roteador de Satélites — Modelo Claude por Frente

## Objetivo

Quando o João Pedro pedir um satélite (chat dedicado a uma frente) ou delegar uma tarefa, recomendar ANTES do despacho qual modelo Claude usar, otimizando três variáveis nessa ordem: (1) qualidade suficiente para a tarefa, (2) velocidade total até a tarefa concluída, (3) consumo de franquia.

O princípio: modelo caro em tarefa mecânica é desperdício sem ganho; modelo barato em peça jurídica gera retrabalho que custa mais que a economia. A eficiência real é medida por tarefa concluída sem correção, não por resposta.

## Formato da recomendação

Ao despachar um satélite, apresente sempre este bloco antes do prompt de abertura:

```
🛰️ SATÉLITE: [frente — ex.: B3 Análise Aprofundada de BO]
🤖 MODELO: [recomendado] (alternativa: [fallback])
⚖️ POR QUÊ: [1 linha]
🔋 CONSUMO: [baixo/médio/alto] — [observação sobre franquia se relevante]
```

Se a tarefa for mista (ex.: extrair + analisar), recomende dividir em dois satélites com modelos distintos, ou rodar no modelo da etapa mais exigente se a divisão não compensar.

## Regras de gestão de franquia

1. Fable consome ~2× Opus e ~3× Sonnet por token. Reserve-o para o HUB e para as frentes da tabela Fable.
2. Uma frente pesada por vez (entrave registrado em 02/06/2026: paralelismo pesado travou todos os chats). Satélites leves (Haiku/Sonnet) podem rodar em paralelo entre si.
3. Em lote grande (>10 registros), prefira o modelo mais barato que sustente a qualidade e aplique o PROTOCOLO_VARREDURA_CONTINUA (checkpoint por registro, parada graciosa a ~70–80% do contexto).
4. Início de semana/janela de franquia renovada: bom momento para as frentes Fable acumuladas (relatórios finais, análises B3).
5. Se o usuário pedir frente não catalogada, classifique pela natureza: mecânica → Haiku; regra explícita → Sonnet; síntese com juízo → Opus; decisão jurídica/peça conclusiva → Fable. Registre a nova frente via aprendizado-continuo.

## Conferência do HUB — completude antes do commit

O HUB roda em Fable justamente para isto: ser a última barreira de qualidade. NENHUM pacote de satélite entra na mestra sem passar pela auditoria de completude. O princípio vem da regra de ouro do cadastro-bo-mestra: linha com coluna vazia por falta de leitura é falha, não opção.

Ao receber um pacote (em `_PARA_LANCAR_NA_MESTRA\pendentes\` ou colado no chat), o HUB confere, nesta ordem:

1. **Cobertura** — o satélite processou TODOS os registros do escopo despachado? Comparar contagem do pacote × lote original. Parada graciosa do PROTOCOLO_VARREDURA_CONTINUA conta como cobertura parcial declarada (não é falha), mas o resto do lote deve virar nova passada.
2. **Completude por registro** — há campo vazio, "não informado" ou "verificar depois" em coluna que os documentos do procedimento permitiriam preencher? Amostragem mínima: 100% em lotes ≤10; nos maiores, todos os registros com campos vazios + 2 aleatórios.
3. **Consistência** — flags de custódia propagadas para as abas certas; números de BO/IP/laudo no formato padrão; datas plausíveis; soma de objetos do pacote × abas de custódia.
4. **Fonte lida por inteiro** — se a síntese cita só a 1ª página do BO ou ignora peças (APFD, oitivas, laudos requisitados), é indício de leitura parcial: nova passada obrigatória.

### Veredicto da conferência

Apresentar sempre um destes dois blocos:

```
✅ CONFERIDO: [frente / pacote] — [N] registros, completo e consistente
→ Autorizado o commit na mestra (backup → prévia → confirmação → aplicar)
```

```
🔁 NOVA PASSADA NECESSÁRIA: [frente / pacote]
📋 LACUNAS: [lista objetiva — registro X sem coluna Y; peças do BO Z não lidas]
🛰️ ESCOPO DA REPASSADA: somente [registros/campos faltantes] (não refazer o que está bom)
🤖 MODELO: [mesmo modelo se a falha foi de cobertura/contexto; um nível acima se a falha foi de interpretação]
→ Lançar na mestra SOMENTE o que já está completo; o restante aguarda a repassada
```

### Regras da nova passada

- Escopo cirúrgico: a repassada recebe apenas os registros/campos com lacuna, com a lista exata do que falta — nunca "refaça tudo".
- Falha de volume (contexto estourou, parou no meio) → mesmo modelo, lote menor. Falha de juízo (tipificação errada, campo mal interpretado) → modelo um nível acima na matriz.
- Mesma frente exigindo repassada 2 vezes seguidas pelo mesmo motivo → registrar o padrão via aprendizado-continuo e corrigir o prompt de despacho da frente (a causa é o despacho, não o satélite).
- O commit parcial é preferível a represar: o que está completo entra; o que falta fica rastreado no bloco 🔁 e, se for o caso, em linha de BACKLOG na AGENDA.
